# وثيقة مواصفات المشروع

الإصدار 1.0 — وثيقة المتطلبات الأساسية

## 1. فكرة المشروع

إنشاء نظام ويب متكامل لإدارة المجموعات الكشفية والإرشادية، ويشمل:

- المجموعة البحرية ومجموعة المرشدات.
- حوالي 3000 فرد كبداية، مع قابلية التوسع.
- إدارة الأفراد والفرق والأرهط والمراحل والسنوات الكشفية.
- الحضور والغياب والأعذار والأنشطة والاجتماعات.
- الاختبارات والشارات والتقدم والمهام والتقارير.
- إدارة الصور والفيديوهات والمستندات.
- نظام صلاحيات دقيق وأمان ونسخ احتياطية.

النظام يبدأ محليًا على جهازك، وبعد اكتماله واختباره يتم نقله إلى استضافة Hostinger مناسبة.

## 2. التقنيات المعتمدة

| الجزء                  | التقنية                             |
| ---------------------- | ----------------------------------- |
| الواجهة الأمامية       | React                               |
| الخادم والـ API        | Python + Django REST Framework      |
| قاعدة البيانات         | PostgreSQL                          |
| إدارة الكود والإصدارات | Git بمستودع Private                 |
| قاعدة بيانات الأفراد   | PostgreSQL، وليس Excel              |
| الاستضافة              | محليًا أولًا، ثم Hostinger          |
| بيئة الاختبار          | منفصلة عن النظام الفعلي، للأدمن فقط |

يجب التأكد من دعم خطة الاستضافة لـ Django وPostgreSQL وتخزين الميديا قبل اختيارها نهائيًا.

## 3. الهيكل التنظيمي

النظام يدعم هيكلًا مرنًا قابلًا للتعديل:

- القيادة العامة.
- قيادة المجموعات.
- قائد المجموعة.
- قائد القطاع.
- قائد المرحلة.
- قائد الفريق.
- مسؤول العهدة.
- السكرتارية.
- المساعدون.
- أدوار إضافية ينشئها الأدمن.

كل فريق يحتوي على أرهط، والأرهط تقسيمات للأفراد وليست حسابات مستقلة.

يجب دعم نقل الفرد بين الرهط والفريق والمرحلة مع الاحتفاظ بسجل انتقالاته السابقة.

كما يجب دعم الأنشطة التي تُقام في نفس الوقت لفرق مختلفة وفي أماكن مختلفة.

## 4. نظام المستخدمين والصلاحيات

### الأدمن

الأدمن يمتلك صلاحية كاملة لكل أجزاء النظام، ويستطيع:

- مشاهدة جميع الفرق والبيانات والسجلات.
- إنشاء المستخدمين وتحديد صلاحياتهم.
- إدارة الإعدادات والنسخ الاحتياطية والموافقات.
- مراجعة سجلات النشاط والأمان.
- التحكم في البيانات التي تظهر لكل مستخدم.

لوحة الأدمن الرئيسية تعرض الفرق بشكل منفصل. عند فتح أي فريق، تظهر جميع بياناته في أقسام منظمة.

### قوالب الصلاحيات

- قوالب جاهزة للأدوار الشائعة.
- عند إنشاء مستخدم جديد، تُنسخ صلاحيات القالب إليه.
- بعد ذلك تصبح صلاحياته مستقلة.
- تعديل القالب لا يغير صلاحيات المستخدمين الحاليين.
- تعديل صلاحيات شخص لا يؤثر على أي شخص آخر.

كل قسم يحتوي على صلاحيات منفصلة، مثل العرض والإضافة والتعديل والحذف والاسترجاع والتصدير.

يمكن أيضًا تحديد نطاق البيانات لكل مستخدم: فريق أو أكثر، مرحلة أو أكثر، ورهط أو أكثر.

ولا تظهر تقسيمات الفرق للقادة تلقائيًا؛ الأدمن يحدد بنفسه من يحق له رؤيتها.

### جلسات الدخول

- لكل قائد جلستان نشطتان كحد أقصى.
- تسجيل الدخول من جهاز ثالث يُرفض حتى ينهي المستخدم جلسة قائمة.
- الأدمن يستطيع مشاهدة الجلسات النشطة وإنهاء أي جلسة عن بُعد.

## 5. إدارة الأفراد

كل فرد يمتلك ملفًا شخصيًا شاملًا يتضمن:

- الاسم الكامل والصورة وتاريخ الميلاد.
- رقم الهاتف وهاتف ولي الأمر والعنوان.
- الرقم القومي عند الحاجة.
- المجموعة والمرحلة والفريق والرهط.
- الحضور والغياب والأعذار.
- الاختبارات والشارات والمهارات والدورات والإنجازات.
- الملاحظات والمستندات وسجل الانتقالات.

### استيراد Excel

Excel مصدر لاستيراد البيانات وتحديثها فقط، وليس قاعدة البيانات الأساسية.

قبل تنفيذ الاستيراد، يعرض النظام معاينة توضح الأفراد الجدد والتعديلات والتعارضات.

منع التكرار: الاعتماد على الكود الداخلي الثابت لكل فرد، مع استخدام الرقم القومي للتحقق من التكرار إن وُجد.

يدعم النظام أيضًا إضافة الأفراد يدويًا، والحقول المخصصة التي يستطيع الأدمن إنشاءها وتعديلها دون تعديل الكود.

## 6. الأكواد وQR

- لكل فرد QR ثابت لا يتغير عند الانتقال بين المراحل أو الفرق.
- الكود الداخلي فريد داخل المرحلة، ويتغير عند انتقال الفرد إلى مرحلة أخرى.
- الاحتفاظ بالأكواد القديمة للبحث والتدقيق.
- الأدمن يحدد صيغة الكود، مثل `SC-27-A-001`.
- مسح QR يتم داخل النظام، ويسجل هوية من أجرى المسح ووقته.
- منع تسجيل حضور الشخص نفسه أكثر من مرة في النشاط نفسه.

النظام أونلاين فقط. لا توجد خاصية Offline أو مزامنة لاحقة.

## 7. الحضور والغياب والأعذار

الحالات الأساسية ثلاث فقط:

- حاضر.
- غائب.
- عذر.

يدعم النظام التسجيل بالـ QR أو يدويًا حسب الصلاحيات، مع إمكانية تعديل الحضور في أي وقت.

كل تعديل يسجل الحالة السابقة والجديدة، ومن قام بالتعديل ووقته.

### اعتماد الأعذار

العذر يحتاج موافقة ولا يُعتمد تلقائيًا.

يستطيع الأدمن تحديد المسؤول عن الاعتماد حسب الفريق أو المرحلة، مع إمكانية تعيين أكثر من مسؤول عند الحاجة.

تظهر الأعذار المعلقة في لوحة المسؤول، وتُحفظ قرارات الموافقة والرفض وتواريخها.

## 8. الأنشطة والاجتماعات

تقويم موحد للمجموعة، مع إمكانية تخصيص الأنشطة لفريق أو مرحلة أو أكثر.

كل نشاط يحتوي على الاسم والمكان والتاريخ والوقت والمسؤول والفرق المشاركة.

يدعم النظام:

- أنشطة متعددة في اليوم.
- أنشطة متزامنة في مواقع مختلفة.
- تكرار الاجتماعات والأنشطة أسبوعيًا أو شهريًا.
- تعديل موعد واحد فقط أو جميع المواعيد القادمة.
- تذكيرات قبل الموعد بأسبوع أو يومين أو يوم.
- تقويم للأنشطة والمهام والاجتماعات والمواعيد المهمة.

كل مستخدم يرى التقويم الخاص بنطاق صلاحياته، والأدمن يرى الجميع.

## 9. الاختبارات والشارات والتقدم

يدعم النظام متابعة تقدم كل فرد في مرحلته، وفق شروط قابلة للتعديل، مثل:

- درجات الاختبارات.
- إنجاز الشارات.
- اجتياز المقابلات إن وجدت.
- شروط إضافية يحددها الأدمن.

تظهر حالة الإنجاز والتقدم في الملف الشخصي ولوحات المتابعة، مع تقارير حسب السنة والمرحلة والفريق والرهط.

## 10. المهام والإشعارات

لكل قائد لوحة مهام خاصة به.

تشمل المهام:

- تعيين المهمة للنفس أو لقائد أو أكثر.
- تاريخ الاستحقاق والأولوية والحالة ونسبة الإنجاز.
- الأولويات: عاجل، مرتفع، عادي، منخفض.
- تكرار أسبوعي أو شهري.
- مرفقات وتعليقات عند الحاجة.
- سجل كامل لتغييرات المهمة.

الإشعارات ستكون داخل النظام في الإصدار الأول، مع إمكانية إضافة البريد الإلكتروني أو WhatsApp أو Telegram لاحقًا.

## 11. نظام الموافقات

الأدمن يحدد العمليات التي تحتاج موافقة مسبقة، مثل بعض التعديلات الحساسة أو اعتماد الملفات.

عند رفض الطلب:

- يظهر سبب الرفض لصاحب الطلب.
- يستطيع صاحب الطلب تعديل الطلب وإعادة إرساله.
- يحتفظ النظام بتاريخ الطلب وقرارات الموافقة والرفض.

## 12. الملفات والمستندات

يدعم النظام رفع صور الأفراد والمستندات وحفظها على السيرفر.

الحدود الافتراضية:

| نوع الملف | الحد الأقصى |
| --------- | ----------- |
| الصور     | 10 ميجابايت |
| المستندات | 25 ميجابايت |

الأدمن يستطيع تعديل الحدود.

تُسمح فقط بالامتدادات المعتمدة، مثل JPG وPNG وPDF وDOCX وXLSX، مع رفض الملفات التنفيذية وغير المسموحة والتحقق من نوع الملف الفعلي.

لا يتم ضغط الصور تلقائيًا، وتُحفظ بجودتها الأصلية.

كل عملية تنزيل تسجل اسم الملف وهوية المستخدم والتاريخ والوقت.

العلامة المائية مؤجلة إلى مرحلة مستقبلية.

## 13. مركز الميديا

قسم مستقل لإدارة الصور والفيديوهات على السيرفر.

يحتوي على:

- ألبومات لكل نشاط أو رحلة.
- تنظيم حسب السنة الكشفية والمجموعة والفريق والمرحلة والنشاط.
- معاينة الصور والفيديوهات والبحث والتصفية.
- صلاحيات منفصلة للعرض والرفع والتعديل والتنزيل والحذف.
- تسجيل من رفع أو نزّل كل ملف ومتى.
- رفع الملفات الكبيرة على أجزاء واستكمال الرفع بعد انقطاع الاتصال.
- عرض مساحة التخزين المستخدمة والتنبيه عند اقتراب امتلائها.

استكمال رفع ملف بعد انقطاع الاتصال لا يعني أن النظام يدعم العمل دون إنترنت؛ كل العمليات تتطلب الاتصال.

## 14. التقارير

يتضمن النظام تقارير جاهزة للحضور والغياب والأعذار وبيانات الأفراد والفرق والمراحل والاختبارات والشارات.

كما يتضمن منشئ تقارير مخصصة يسمح باختيار الأعمدة والفلاتر والترتيب، ثم التصدير إلى Excel أو PDF.

يستطيع الأدمن تحديد ما يظهر في التقارير حسب الصلاحيات.

## 15. الأمان وسجل التدقيق

الأمان من أساسيات النظام وليس إضافة لاحقة.

- تسجيل الدخول باسم مستخدم وكلمة مرور.
- تسجيل الدخول والخروج والجهاز وعنوان IP عند توفره.
- تسجيل محاولات الدخول الفاشلة والتنبيه عند الاشتباه.
- سجل لكل إضافة وتعديل وحذف واستيراد وتصدير وتنزيل واعتماد.
- حذف منطقي مع إمكانية الاسترجاع.
- التحقق من الصلاحيات داخل الخادم والـ API، وليس في الواجهة فقط.
- حماية الملفات والمدخلات والبيانات الحساسة.
- اختبارات آلية قبل التحديثات.
- إمكانية الرجوع إلى إصدار سابق من الكود.

المصادقة الثنائية مؤجلة لمرحلة لاحقة.

## 16. النسخ الاحتياطي

- نسخة احتياطية تلقائية يومية.
- إمكانية إنشاء نسخة يدويًا في أي وقت.
- تضمين قاعدة البيانات والملفات والميديا وفق سياسة النسخ.
- تجميع ملفات النسخ داخل ZIP دون التأثير على جودة الصور والفيديوهات.
- تشفير النسخ، مع الاحتفاظ بمفتاح التشفير منفصلًا.
- إمكانية تحديد مكان التخزين وتغييره مستقبلًا.
- تحديد سياسة الاحتفاظ بالنسخ من خلال الأدمن.
- التحقق من سلامة النسخ وإمكانية استعادتها.
- إنشاء نسخة من الحالة الحالية قبل الاستعادة.
- اختبار الاستعادة في بيئة منفصلة لا تؤثر على النظام الفعلي.
- مراقبة مساحة القرص وصحة PostgreSQL وإرسال تنبيهات للأدمن.

## 17. لوحة الأدمن

تكون لوحة الأدمن منظمة على مستوى المجموعة ثم الفرق.

داخل كل فريق تظهر أقسام واضحة تشمل:

1. الأفراد والأرهط.
2. الحضور والغياب والأعذار.
3. الأنشطة والاجتماعات.
4. الاختبارات والشارات والتقدم.
5. القادة والمساعدون والصلاحيات.
6. المهام والإشعارات.
7. التقارير.
8. المستندات ومركز الميديا.

كما تعرض اللوحة ملخصًا عامًا، وتنبيهات الأمان، وحالة النسخ الاحتياطي، ومساحة التخزين.

## 18. قابلية التوسع وإضافة أجزاء مستقبلية

هذه نقطة أساسية في التصميم.

سيتم بناء النظام على هيئة وحدات مستقلة ومترابطة عبر API، بحيث يمكن إضافة وحدات جديدة لاحقًا دون إعادة بناء النظام بالكامل.

من الأمثلة على الوحدات المستقبلية:

- تطبيق موبايل.
- تكامل مع خدمات الإشعارات الخارجية.
- المصادقة الثنائية.
- العلامات المائية.
- أدوات ذكاء اصطناعي استشارية.
- أقسام جديدة أو أنواع بيانات وتقارير إضافية.

أي وحدة مستقبلية يجب أن تستخدم نظام الصلاحيات وسجل التدقيق وقاعدة البيانات المنظمة، وألا تتجاوز قواعد الأمان القائمة.

## 20. شروط قبول النظام قبل إطلاقه

- المستخدم لا يستطيع الوصول إلى بيانات خارج نطاق صلاحياته حتى عبر API مباشرة.
- تعديل قالب الصلاحيات لا يؤثر على المستخدمين الحاليين.
- استيراد Excel يمنع تكرار الأفراد ويعرض التغييرات قبل اعتمادها.
- تسجيل الحضور لا يتكرر للفرد نفسه في النشاط نفسه.
- العذر لا يصبح معتمدًا إلا بعد موافقة المسؤول المحدد.
- كل تعديل مهم مسجل ويمكن تتبعه.
- الملفات غير المسموحة أو التي تتجاوز الحد تُرفض.
- يمكن استكمال رفع ملفات الميديا الكبيرة بعد انقطاع الاتصال.
- النسخ الاحتياطية قابلة للتحقق والاستعادة في بيئة اختبار منفصلة.
- يمكن إضافة وحدات مستقبلية دون كسر الوحدات الموجودة.
